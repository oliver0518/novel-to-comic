# 角色定妆流水线（v2 双卡体系）

**目标**：把小说里的人物做出一组"写实完整人物卡 + Q 版人物卡"，作为后续所有出图的锁脸基准。

> 这套方法论已经为《凡人修仙传》7 个角色（韩立 / 厉飞雨 / 张铁 / 赤焰 / 清衡 / 程苏生 / 阿溜）完成全员定妆。

---

## 开工第一件事

1. 读本文件「铁律」
2. 读该角色的小说原文出处（`<项目>/<原著名>_文稿/`）
3. 读现有定妆目录 `角色定妆照/<角色>/`，确认哪些编号已占用
4. 读 `templates/character-card.md` 模板

---

## 交付物（缺一不算完成）

| # | 产物 | 路径 |
|---|------|------|
| 1 | 写实完整卡 | `角色定妆照/<角色>/NN_<角色>_完整人物卡.png` |
| 2 | Q 版人物卡 | `角色定妆照/<角色>/NN_<角色>_Q版人物卡.png`（**必须独立成卡，不能塞在写实卡里**） |
| 3 | 分件源图 ×10 | `角色定妆照/<角色>/_分件_<新卡>/`（写实 5 + Q 版 5，**仅返修用，不出片**） |
| 4 | 引用表同步 | 见「第五步」清单 |
| 5 | **旧文件清理** | **同一轮做完，不许留成待办** |

**编号规则**：取该角色目录内下一个空闲编号，惯例 `NN` 写实、`NN+1` Q 版。

---

## 铁律

- **一个人物验收后再做下一个**，不并行。
- **交付 = 两张卡 + 10 分件 + 引用同步 + 旧文件清理**，五项全齐才算完成。
- **角色设定是铁律**，不得自由发挥（来自小说原文/设定大纲）。常见硬性禁项：
  - 程苏生按女角（即使是「他」也按女角画）
  - 清衡无眉心印无眼镜
  - 赤焰人类手禁鬼手
  - 韩立禁外显小瓶（除非该场景需要）
  - 阿溜掌上萌宠约 20cm/1kg 禁画大狗/大猫
- **Q 版只能作搞笑嵌格**（单集 1–3 处、每处 ≤2 秒），禁整镜 Q 化，禁写实↔Q 对切。
- **非人形角色**（如阿溜这种动物灵宠）：
  - 「服饰六格」改「外形细节六格」（软绒/灵纹/契疤/项圈/环尾/爪垫），板块标题用 `acc_label` 参数
  - 「装备六格」可改「叼物战绩」，`eq_label` 自定义
  - 锁脸 `image2` **禁挂穿着衣物的人形角色分件**（服装会串到非人形身上），改挂漫画成品页

---

## 第一步 · 考据（先证据后画）

从 `<项目>/<原著名>_文稿/<原著>_精校版.md` 取证，**逐条带行号**：

- **台词金句**（定性格）→ 例：赤焰「我赤焰可以穷，不能怂」L583
- **生活细节**（定道具/微表情，最容易被忽略也最出彩）→ 例：生火煮粥 L377、竹斗笠 L359、爱赌爱好看 L460
- **战力表现**（定动作/装备）→ 例：火拳、焰纹暴走
- **信物归属必须查通读报告**（别串人）：面具碎片=A、信物=B、...
- **硬性禁项**从 `设定大纲.md` 抄

**产出**：装备六格 + 服饰六格 + 微表情六个 + 身高体重 + 色板（6 色，给 hex + RGB）

---

## 第二步 · 10 张分件生图

**写实 5 张**（锁脸挂 `image1` = 该角色现有定妆原图）：
- `<角色>_主肖像_源图.png`
- `<角色>_三视图_源图.png`
- `<角色>_微表情_源图.png`
- `<角色>_服饰图鉴_源图.png`
- `<角色>_装备图鉴_源图.png`

**Q 版 5 张**（同套命名加 `_Q版`）。

### 生图硬约束

- **锁脸**：`image1` = 该角色现有定妆原图；`image2` = 往期成品页（场景对照）
- `input_fidelity: "high"`
- 提示词第一句写 `CHARACTER LOCK`
- **⚠️ 挂图超限**：高清分件普遍 5–8MB，超 ImageGen 请求体上限报错。**先 PIL 缩到 1200px 高质量 JPG（约 300KB）存 /tmp 再挂**，锁脸不受影响。
- **六格图必须出横版 3 列×2 行（1536×1024）**，否则名牌错位。**方图会错位，必返工。**
- 底色统一浅色（≈240,237,231），否则组装后卡片色带不齐。
- 禁项逐条写进提示词；服饰六格/装备六格**一律素面禁文字标签**。

### 出图后必做目检

目检 10 张源图：额头带子 / 断肢三脚 / 道具文字 / 撞脸 / 鬼手（赤焰类）/ 眼镜与眉心印（清衡类）。

发现问题**当场 img2img 或重出**，别带到组装阶段。

---

## 第三步 · 组装双卡

使用 `tools/` 下的拼卡脚本：

```bash
# 写实完整卡（参考实现，按你的项目改造）
python tools/compose_card.py <角色>

# Q 版人物卡：在你的项目里复制 compose_card.py 改名为 compose_q_card.py，
#              按 Q 版规则（turn_front_x / expr_grid）扩展
python <项目>/_工具/compose_q_card.py <角色>
```

> **项目落地**：每个项目的角色数、布局、色板都不一样，建议**复制
> `tools/compose_card.py` 到你的项目 `_工具/` 下**，按 `templates/character-card.md`
> 的配置定义你的角色字典。`tools/compose_card.py` 是参考实现，不是开箱即用的。

**配置键**（两脚本大同小异）：
- `parts`（分件目录）
- `out`（输出文件名）
- `bust`（大肖像文件名）
- `turn`（三视图文件名）
- `expr`（微表情文件名）
- `acc`（服饰图鉴文件名）
- `eq`（装备图鉴文件名）
- `title`（卡标题）
- `subtitle`（副标题/身份）
- `info_pairs`（资料栏两列键值）
- `info_full`（资料栏单行全宽）
- `traits`（性格特征标签）
- `ability`（能力简介）
- `background`（背景故事）
- `world`（所属世界观/势力）
- `palette`（色板 6 色 hex）
- `acc_names` / `eq_names` / `eq_notes`（六格标题与注解）
- `expr_names`（微表情六格标题）
- `cm_height`（身高 cm，刻度线自动按此生成）
- `acc_label`（服饰/外形板块标题，非人形角色改名）
- `eq_label`（装备板块标题，非人形角色改名）
- `foot`（页脚版权/署名）

Q 版额外：
- `turn_front_x`（正面视图的 x 范围）
- `expr_grid`（**横版 2×3 填 `(3,2)`**）

### 已知坑位

| 坑 | 症状 | 解法 |
|----|------|------|
| 微表情名牌错位 | 源图出成方图 | 重出横版 2×3，验证名牌带间距 = 半行高 |
| 三视图水印补丁露色块 | `fill_wm` 在地面渐变上出色块 | 改 `turn_wm="stretch"`，取人物间地面空隙拉伸贴盖 |
| `patch_wm` 复制带进靴子 | 侧面视图串元素 | 同上，用 `stretch` |
| Q 版刻度线失效 | 身高线 top=0 | `detect_figure_span(ref=None)` 动态四角采样背景色，别写死 RGB |

组装后 **PIL 读尺寸**确认出图成功，并**真目检成品卡**（人类手 / 无多余特效 / 名牌对齐 / 刻度线贯通）。

---

## 第四步 · 目检成品

两张卡都要看：写实卡（大肖像 + 资料栏 + 统一刻度三视图 + 微表情 + 服饰六格 + 装备六格 + 色板 + 背景/世界观）、Q 版卡（同上但 Q 化）。

检查名牌是否与格子一一对应、刻度线 10cm/50cm 分级是否贯通。

---

## 第五步 · 同步引用表

逐处 grep 复核（具体清单按项目调整，常见 6–8 处）：

1. `<项目>/<原著>/设定大纲.md` 人物谱
2. `角色定妆照/README.md` 目录
3. `.cursor/rules/character-sheet.mdc` 默认引用
4. `<项目>/<原著>/分析/漫改大纲.md` 出场表
5. 各 skill 的 SKILL.md 中的锁脸表
6. 工作区 `MEMORY.md` 主用总卡条
7. 已出集的 `发布文案.md`（角色引用）
8. `tools/` 里的 `compose_*.py` 配置段

**⚠️ Edit 工具可能报成功但未落盘**——每次改完必须 grep 复核实际内容。

### 校验引用

```bash
python tools/check_refs.py .                # 全仓库扫描
python tools/check_refs.py <项目子目录>       # 只扫指定
```

要求 **0 缺失**。

---

## 第六步 · ★ 旧文件清理（强制，同一轮做完）

**这一步最容易漏——交付两张卡不等于闭环。**

1. **先存证**：`md5` 每一件待删文件，记进当日日志（可核对废纸篓）
2. **扫描引用**：确认无其他 md/mdc/py 引用旧路径
3. **删**：
   ```bash
   # macOS 优先用系统 trash（可恢复）
   # Linux 用 trash-cli
   # 永远不用 rm -rf
   ```
4. **删后目录应只剩**：旧期定妆（闪回用）+ 两张 v2 卡 + `_分件_<新卡>/`
5. **补齐记录**：检查 MEMORY.md 是否有指向已删旧卡的悬空引用

---

## 第七步 · 日志

- 追加到 `<项目>/memory/YYYY-MM-DD.md`：考据要点（带行号）、生图返修次数与新坑、成品路径与尺寸、引用更新处数、清理 md5 清单、教训。
- 长期规则变化写进 `<项目>/memory/MEMORY.md`。
